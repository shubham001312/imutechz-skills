# Fish Video Skill

You make one video from one conversation. Quality comes from the tools, not from your taste: follow the numbered path, run each command, and stop where it says STOP. Every frame needs a real image, footage or drawn graphic, never only words.

Run commands with the skill's venv: `.venv/bin/python scripts/fishvideo.py <cmd>` (Windows: `.venv/Scripts/python`). Below, `fv` means that.

## The path (do not skip, do not reorder)

1. **Setup.** `fv doctor --keys`. Install what it lists as missing (`npm install` also fetches the theme fonts; render stops if they are missing). If `qwen3` is missing, tell the user and run `fv voice setup --engine qwen3` (one command, the recommended voice; add `--gpu` on an NVIDIA machine). STOP if `doctor` shows no browser or no ffmpeg.
2. **Pick a recipe and a theme.** `fv recipes`, then `fv themes`. Roadmap, guide or "how to become" = `roadmap-explainer`. True story, history = `story-short`. Real people in the news (actresses, actors, celebrity stories, fact series) = `news-short`. Facts, rules, deadlines with no photos = `bold-short`. A tool, repo, app or AI news ("this free tool replaces X", "top 3 Claude skills") = `kinetic-explainer`: off-white canvas, words stacking on their spoken word, pills, screenshot cards, orbit diagrams, cut-out heroes. A recipe is a starting default (beats, pacing, gates), not a fixed structure: the live trend direction (step 4) may change it. Theme choice happens in the interview, after step 4 (`fv themes preview` renders a gallery of the built-ins).
3. **Create.** `fv new projects/<slug> --recipe <id> --prompt "<the user's words>"`. You get a brief, a storyboard skeleton full of TODOs and `assets/PLAN.md`.
4. **Research live trends (required; this sets the direction).** `fv trends projects/<slug>` searches the topic in its format over the last 30 days (90 if thin), ranks by views per day, separates Shorts from long videos, and writes `research/trends.json`, `research/trends.md` and a contact sheet `research/trends-contact.jpg`. OPEN the contact sheet and read the table, then replace every TODO in the Analysis of `research/trends.md` with facts from this run (cite result numbers): the common hook, pacing, thumbnail and colour patterns, the closest built-in theme and why, what this video takes, and the `direction:` block (hook, pacing, layout, thumbnail, palette). With fewer than 5 results say the data is thin and claim no trend; never invent one. Then `fv trends <dir> --derive-theme` builds a project theme from the fetched thumbnails (offered first in the interview; the 15 built-in themes are fallbacks). The direction may change beat order, pacing, scene types and layouts; every quality gate still applies. These files are analysis only: never use a result's script, images or look, never commit or package them. `gate` fails if the research is missing, older than 14 days, thin, or the analysis is empty. Only if search is really down: `fv trends <dir> --unavailable "<reason>"` (recorded; built-in themes are used; tell the user in the final report).
4b. **Pick the audio (required, right after `trends`).** `fv trends <dir> --sounds` lists the sounds or music named in the trending videos' own metadata (title, description, tags, music fields) and the common style, into `research/trend-sounds.md`; where the data names nothing it says so. Popular tracks and viral sounds are copyrighted: they are never downloaded or embedded. To use a trending sound the licensed way, the user attaches it in YouTube's own Shorts editor ("Add sound") at upload. Inside the video: `fv music source <dir>` finds a CC0 or CC BY track matching the trend style, confirms the licence on the track's own API record, and writes the credit; with none found it says the synthesised score is used. Each project gets its own score (mood, key, mode, progression, BPM, instruments, seed) from `scripts/score.py`, stored in `<dir>/score.json`, and the music changes by section with scene energy and thins under `reveal`/`punchline` lines. A track the user supplies goes in through `assets adopt` with the licence-risk label. Sound effects: the licensed `sfx` library or the opt-in manual route, nothing automatic.
5. **Interview, once.** `fv interview projects/<slug>`, ask every open question (every question has a Recommended option; with no question tool such as AskUserQuestion, ask in one plain message listing the options with the recommended one first, wait for the reply, then record it with `--set`; never answer for the user) (length, ending, theme and voice included; "Under 30 s Short (Recommended)" and "Seamless loop (Recommended)" come first, and the voice option "Qwen3 Ryan storyteller (Recommended)" comes first; a longer cut only when the user picks it), record answers with `--set`, read `--summary` back, then `--confirm`. After this, ask nothing until the final review. STOP until confirmed.
6. **Collect real assets, beat by beat.** `fv assets source <dir> "<what the beat shows>" --beat <id>` searches Wikimedia Commons, NASA, the Library of Congress (plus Pexels/Pixabay when keyed), keeps only licences the API confirms, downloads, records source, licence and author in `assets/credits.json` (they flow into every post text) and points the beat at the file, labelled `illustrative`; add `--depicts "<who or what>"` only when the picture truly shows it (label `archive photo`). `fv assets plan <dir>` lists beats still without an image. Also: `fv capture` (screen-record a website tour), `fv assets shot <dir> <url>` (a screenshot), `fv assets github <dir> <owner/repo> [--shot]` (the repo's card plus its stars, licence and description written into `brief.facts` with the source), `fv assets terminal <dir> --cmd "..."` (a terminal card; output lines you write are labelled illustrative), `fv assets logo` and `fv thumb logos --find <brand>`, `fv assets clip` (cut a licensed video), `fv assets cutout` (a cut-out hero; needs `rembg`). Pexels and Pixabay need free keys; without them the key-less sources are used and the skip is printed. Open the previews and look. STOP if most beats have no real image; text-only beats are a small minority.
7. **Write the storyboard.** Replace every TODO: narration (short concrete lines, one surprise per line, tease before the pay-off, no filler; the first line under 10 words; tag a line `{text, tag: hook|setup|reveal|punchline, pause: 0.5}` to shape its delivery within the voice preset's range, `pause` only for a reveal and at most 0.8 s), on-screen words (6 words or fewer, one `*accent*`), params. Use `story`, `site`, `cards`, `flow`, `roadmap`, `bold`, `kstack` scenes ([scene catalogue](references/scene-catalogue.md)). Script to the confirmed length (about 3 words per second: 28 s is about 80 words). With `ending: loop` the last line must flow into the first (no full stop at the end) and the last frame must match frame 0; [storyboard templates](references/storyboard-templates.md) has beat grammars for facts, story, tool and myth-buster Shorts. Facts need `brief.facts` with a source. Follow the `direction` from step 4 for beat order, pacing and layouts (new scenes and custom layouts are allowed when it calls for them; the gates apply to whatever you make). Write `brief.publish` (5 titles, description, tags) and the `thumbnail:` block (below).
8. **Gate the script.** `fv gate projects/<slug>` must say `ready`, and `fv gates projects/<slug>` must PASS (it also runs inside `gate`/render for every video): most beats have a real image or footage that exists and is credited (source, licence, author), photos of people or events carry `label: archive photo|illustrative`, a site screenshot is never the main visual, and images keep arriving. The only opt-out is `visuals: {mode: abstract, user_asked: true, reason: "<the user's words>"}` when the user asked for an abstract or text-led video. STOP and fix on any BLOCKED or FAIL: add real images to text scenes, split long scenes, use `srcs:` to swap photos inside a scene.
9. **Voice.** First `fv budget <dir>` (words per beat slot, before any minutes-long voice run). Then `fv voice projects/<slug>` (Qwen3 Ryan by default, each sentence directed by its mood and `tag`, then paced to the target; only changed lines are re-voiced; about 5 s of compute per second of speech on a CPU). If the words check flags a homophone ("emus" heard as "emos"), `fv voice words <dir> --add emos=emus`; no re-voicing needed. Then `fv storyboard projects/<slug>`. If the engine is not installed the command stops and prints the setup command; it never switches voice silently. If the user picks another voice, say what changes.
10. **Look before rendering.** `fv stills projects/<slug> --scenes`, open every still. Fix empty frames, text under the platform UI, unreadable captions.
11. **Render.** Narration drives time: scene cuts follow the last word and the next line starts 0.15-0.35 s later (`pacing.snap: speech`, the default; `bar` is the old 2 s grid, opt-in). The music moves to the speech, never the voice to the music. `fv qa` reports the median and maximum gap between lines and fails an unplanned gap over 0.6 s. Preview the hardest 10 s: `fv render <dir> --scale 0.5 --fast --from 8 --to 18`. Then `fv render <dir>`.
12. **QA and the frame sheet (required).** `fv qa <dir>`, then `fv review <dir> --platform <p>` and `fv signoff <dir> --platform <p>`. Open every sheet and `build/<p>/contact.png`. Fill `build/<p>/review/SIGNOFF.md`: for every scene one sentence naming every object you see (4+ words) and a verdict `ok` or `fix`; tick the checklist. Fix every `fix`, re-render, sign again. Check with `fv signoff <dir> --check`. STOP until it passes. Never score a video out of 10; list the changes instead.
13. **Thumbnail (required).** Keep the headline-and-road design, but its words, palette and tile choice come from the direction. Put the brands the video is about in `storyboard.yaml -> thumbnail: {title, accent, tag, sub, logos: [slug, ...]}` (find slugs with `fv thumb logos --find <name>`; a topic with no brands uses its licensed pictures automatically). Run `fv thumbnail <dir>` (`fishvideo thumbnail`): it draws the headline-and-road design (plus a 9:16 cover for Shorts), runs the checks and picks it. Open the PNG. `package` refuses without it. `--no-thumbnail` only if the user asks for none. A website screenshot is never a thumbnail or cover. Kinetic-explainer videos get the insider cover instead (light, hero on top, huge keyword, black chip: `thumbnail: {lead, title, mid, chip, hero: {src, kind: cutout|card} or logos}`); others keep the road design.
14. **Package.** `fv package <dir>`. It refuses, naming the failing checks, if QA has any FAIL, or if the thumbnail or sign-off is missing. Fix and re-run `fv qa`. Only if the user explicitly accepts a failure: `--accept-qa-fail "<their words>"` (recorded in the package).
15. **Final review.** Send the user: the folder path, the video, the thumbnail, 5 titles, measured loudness, anything still open (a WARN, an estimated voice). Ask for approval or changes.
16. **Clean up after approval.** Ask for approval of the video and the cleanup in one question. On a yes: `fv clean <dir> --final-only` (dry run, tell the user the size), then `fv clean <dir> --final-only --yes`. It keeps only `out/`: the video, thumbnail, covers, captions, post texts, titles, tags, transcript, credits, metadata.json, plus a copy of brief.yaml and storyboard.yaml. Everything else is deleted (build/, assets/, research/, reference/). It refuses if out/ has no video or no credits.

## The defaults you must not change without the user asking

- **Voice:** Qwen3-TTS speaker Ryan, style `storyteller`, pace `fast` for Shorts (target 3.3 words per second, measured about 3.0): one sentence at a time with a plain-English instruction from the style, the line's mood or tag and its punctuation; silences inside a take cut to 0.12 s, then pauses and a time-stretch of at most 1.3x land the pace. `chatterbox-soft` remains a calmer choice. Details: [local voices](references/local-voices.md).
- **Length:** under 30 s for every Short unless the user picks longer in the interview. **Ending:** a seamless loop unless the user picks a CTA.
- **Looks:** the trend-derived theme from step 4 (`--derive-theme`), else one of the 14 built-in themes (`theme:` in the brief); `theme_overrides:` changes single values. [Recipes and themes](references/recipes-and-themes.md).
- **Imagery:** the recipe's gate thresholds (`fv gates`). A text-card video fails.
- **Thumbnail:** `fv thumbnail`. Logos must relate to the video's content; they are trademarks of their owners.

## Hard rules

- One interview at the start; never write a script before it is confirmed. Never ship template text: the gate blocks TODOs, lines copied from `examples/`, example image files, and a scene sequence identical to the recipe skeleton or a bundled example (apply the trend direction).
- `examples/` are past outputs and a quality bar, not templates; the skill does not need them to run. Set the direction from live `trends` first; open an example only afterwards, to compare quality. Never copy its structure, words, images or look because it is there.
- Explainers need a diagram (`diagram`, `whiteboard`, `neonline`, `flow`, `roadmap` or a `split` reveal).
- Never invent facts, numbers, quotes or logos; every number is in `brief.facts` with a source.
- Licences: never NC or ND, never a non-CC YouTube video, never a reference video's footage. Memes and viral sounds only with the user's opt-in (`memes.policy`). Every asset is in `assets/credits.json`.
- Film websites read-only. Keys live in `.env` only; never print or commit them.
- Renders run at low priority under a CPU cap; run heavy jobs one at a time. Scene code is deterministic (no `Math.random`, `Date`, CSS animation).
- Do not upload or publish. Never clean before the user approves the final video. `--no-gate` and `--no-thumbnail` are for tests and explicit user requests only.
